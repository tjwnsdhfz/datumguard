# DatumGuard 품질 검토 — 2026-10-28

검토 기준은 `origin/main`의 `73f5504df7e8f1a32cd266ad4cbbda24e1c2c1ff`이다.
star는 비교 대상을 고르는 조건이며 정확성·보안·제품 완성도의 보증으로 사용하지 않는다.
기존 v0.4 기능을 다시 구현하지 않고, 공개 사용 경로의 재현성과 실패 처리를 검사했다.

## 판정

현재는 다분야 CAD 검증을 시연하는 공개 MVP이다. 산업용 설계 승인 제품이나
1만 DAU 검증 서비스로 표현할 근거는 없다. 독립 파일 재측정·실패 시 export 차단·
고정 fixture라는 강점이 있지만, 의존성 유지관리와 편집 후 승인 무효화에 실제 결함이 있었다.

이번 검토의 완료 산출물은 보안/동작 수정, 회귀 테스트, 비교 근거, 단계별 품질 기준이다.
이 문서의 완료 표시는 해당 branch에서의 검증을 뜻하며 production 배포 완료를 뜻하지 않는다.
기존 source 작업·Rhino 파일은 원본 checkout에 보존했다.

## 4. 다음 기능 개선 순서

### 출시 전 우선

1. 이 branch의 Linux CI·container build·보안 검사를 통과시킨다.
2. 배포 후보에서 실제 API SHA, 정상/실패 CAD, edit-after-PASS, capability-disabled 경로를 확인한다.
3. critical/high advisory가 없는 lock을 사용한다. 경고를 ignore 목록으로 숨기지 않는다.
4. 기존 Render 환경변수는 blueprint 변경만으로 반영됐다고 가정하지 않는다.
   `DATUMGUARD_TRUST_CF_CONNECTING_IP=false` 적용 여부와 실제 사용자 IP·429 동작을 staging에서 확인한다.
5. PR #33 CLI/Action을 main 최신 API와 재검증하고 공개 release를 만든 후 시작 경로로 소개한다.

`tests/test_pipeline.py`에는 이미 100개 폭 변형 golden matrix와 숫자를 바꾸는 50개 자연어
guard 회귀가 있다. 개수 자체는 갖췄지만 독립된 100개 설계 사례·50개 실제 요청의 다양성을
검증한 benchmark와는 구분한다.

현재 Architecture의 Grid/Wall/Column/Door/Window 도구는 객체 선택·편집 중심이며,
새 객체 생성 기능이 모두 구현된 CAD 편집기로 소개하면 안 된다. 가져온 column의 rotation도
현재 canvas에서 완전히 표현되지 않는다. 이번 복구 수정은 유효한 project 초안의 저장·복원을
보장하는 범위이며, demo 전용 locked dimensions를 임의 프로젝트에 맞게 자동 재정의하지 않는다.
범용 편집으로 확장할 때는 객체 생성·삭제, rotation 표현, dimension 참조를 함께 검증해야 한다.

## 5. 에이전트 task evaluation 계약

각 task는 입력 fixture/요청, expected status/error ID, artifact hash 또는 쓰기 여부,
실행 환경·commit·소요 시간·pass/fail을 기록한다. 아래 표는 평가 설계이며 아직 실행 완료한
10개 agent benchmark 결과로 표시하지 않는다.

| Task | 요청 | 기대 결과 |
|---|---|---|
| E01 | 정상 plate contract를 검증·export | passed, 독립 DXF measurement 및 bundle |
| E02 | 모호한 단위 입력 | needs_confirmation, 수치 추정 없음 |
| E03 | locked 치수 충돌 | infeasible 및 관련 ID, export 없음 |
| E04 | 저장 DXF endpoint 변조 | failed_verification, bundle 없음 |
| E05 | NaN/Infinity datum/tolerance | 입력 거절, geometry worker 호출 없음 |
| E06 | oversized/invalid base64 | encoded 크기 초과는 decode 전 차단; malformed는 strict decode 오류; decoded byte 한도도 확인 |
| E07 | workspace 밖 export/link | 거절, 바깥 파일·폴더 변경 없음 |
| E08 | PASS 이후 편집 중 늦은 응답 | 오래된 PASS/다운로드 노출 없음 |
| E09 | JSON project 저장·복구 | 임의 유효 ID·room 수 보존, 해시/계약 재확인 |
| E10 | disabled capability와 오류 후 재시도 | 지원 범위 설명, 정상 지원 샘플로 복구 |

## 6. 실행과 복구

변경 전 source는 `73f5504df7e8f1a32cd266ad4cbbda24e1c2c1ff`이며 기존 worktree는 유지한다.

실제 merge 후 문제가 발생하면 수정 commit을 `git revert <commit>`한 별도 PR로 복구한다.
다만 이전 lock에는 확인된 취약점이 있으므로 dependency downgrade는 노출을 재도입한다.
긴급 배포 복구는 취약 기능 비활성화와 known-good deployment를 함께 검토한다.
stateless API에는 DB migration이 없고, 본 변경은 IndexedDB 사용자 자료를 삭제하지 않는다.
